The maintainer authorized these fixes, rebuilding and installing this development

## Planner stability

The previous-trip safeguard formerly searched only the groups generated by
score-improving greedy insertion. A previous group could remain valid and close
to the best score yet fall out of that search. A preference for the previous
next action then changed ordering and scores in ways that caused alternating
recommendations on otherwise unchanged snapshots.

Dev 3 independently rebuilds the previous group from **current** quest data before
comparison, even when greedy insertion or the sixteen-candidate shortlist omits
it. It accepts only canonical keys containing one to four unique current quest
IDs, rechecks eligibility and quest-log capacity, and projects prerequisite
returns only through resolved members of that same group. Missing/removed,
skipped, completed, failed or unlocatable members cannot be blindly retained;
unknown stages cannot unlock children. No saved scores or coordinates are reused.

The existing 85% retention threshold still applies. A materially better plan or
an eligible pin can replace the previous group. Accepted timed deliveries,
actual nearby ready returns and bounded field continuation retain their earlier
priority. The rebuilt group participates in the available XP comparator for
gear allowance, because it is a currently valid candidate. Existing batching,
manual player control, catalogue data and waypoint ownership remain in place.

## Feedback attribution

Immediate next/later-plan matches keep their current labels. When an acceptance
matches a recently recommended pickup that has disappeared from the immediate
plan, the event instead records **recently_recommended**, with bounded source
recommendation evidence. This distinct label does not claim the pickup was still
next at the instant of acceptance. An offered quest alone is not a recommendation.

Recent recommendation history is transient, limited to ten seconds and twenty
observations, capped at 128 quest IDs, and restricted to the same map. Loading,
unavailable data, map changes, reload/clear and clock discontinuities invalidate
it. Skipped/completed/failed quest state cannot supply stale evidence. Both
explicit acceptance events and snapshot-only acceptance use the attribution.
The event's immediate context stays separate from its earlier recommendation.
History covers all 24 visible route steps; a pickup beyond the ordinary eight-step
export context retains an identified source-step excerpt and its original index.
Source evidence keeps the numeric plan, location and settings while omitting
redundant active-quest and offered-quest snapshots; the immediate event retains
its existing context. Only allowlisted fields are retained; no automatic
names, chat, quest prose or new inventory data is captured.

The 300-entry ring, monotonic identifiers, old build tags, prior notes and safe
reader behavior are preserved. Existing historical unplanned labels are not
retroactively rewritten. New records carry planner/capture tag 9 so subsequent
reviews can distinguish the implementation; UI dev 1/2 used tag 8.

## Verification and evidence limits

The source-level oscillation mechanism was previously reproduced with a private,
fixed-position/progress replay. After the fix, the same bounded replay retains
one route throughout sixteen calls. It is an investigation reproduction, not an
exact game replay: the export does not contain every input. Private snapshot data
and results remain ignored; no raw game save or private fixture is committed.
Public tests use independent synthetic inputs and exercise omission, invalidation,
capacity, prerequisites, priority, capture expiry/evidence and data preservation.
Consolidated results are in VALIDATION.md; independent review findings are linked
from HANDOFF.md. UI dev 2's accepted drag fix remains unchanged apart from version
identification. Actual new planning and attribution in Forever require playtesting.

   a similar quest area without progress changes; the next instruction should
   remain stable. Actual progress, a nearby ready recipient, urgent delivery or
   a substantial priority change must still update the plan.
2. Check grouped work, turn-ins, a pin/skip and changed quest-log capacity. Confirm
   missing locations remain reminders and no completion is inferred from arrival.
3. Open a quest offer, let the tracker recommend its pickup, then accept manually.
   After playing, reload/log out and request a saved-feedback review. A recent
   recommendation may explain acceptance without being mislabeled as current.

evidence, not live planner or feedback acceptance.
