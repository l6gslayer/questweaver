# Independent initial review: WoW implementation quality

Reviewed approved build 8 using `git show main:QuestWeaver/UI.lua`, related runtime/navigation/feedback source, and UI simulation tests. No other reviewer reports or proposed design were consulted. The same reviewer previously performed the visual critique; this is a separate technical pass, not a fourth reviewer identity. No live client behavior is claimed.

| Severity | Weakness and evidence | Impact | Highest-value improvement |
| --- | --- | --- | --- |
| P1 | Manual native-waypoint fallback calls optional functions directly without protected invocation (`Runtime.lua`, `R.Waypoint`), unlike the TomTom integration's `pcall` guards. Button enabled-state only tests existence of a step/action (`UI.lua`, `Render`), whereas `Navigation.Destination` validates coordinates. | A present-but-failing optional API can break the explicit interaction; UI affordance can disagree with usable destination availability. | Reuse validated destination semantics; protect optional native functions and report an actionable coordinate fallback without touching another addon's points. Add failure and invalid-target interaction regressions. |
| P2 | `SavePosition` divides `GetLeft/GetTop` by parent dimensions without nil/zero checks, while `Place` accepts any numeric position including non-finite values (`UI.lua`, position helpers). Layout has fixed 640 height and no display-size-change handler. | A transient unlaid-out frame, malformed old setting, small UIParent, or display change may fail or make controls unreachable. | Guard dimensions and finite coordinates, preserve existing normalized schema, clamp size/position against current screen, and recalculate after display/UI scale changes using supported events. Test recovery from invalid saved positions and constrained screens. |
| P2 | Passive main frame explicitly enables mouse across its full rectangle (`UI.lua`, `Create`). Locked state disables only the drag frame. | Even locked reading areas consume world clicks; expanded tracker is a large obstruction. | Make passive regions click-through where compatible, with explicit mouse ownership for buttons/scroll/drag; verify native behavior in-game and document the chosen interaction boundary. |
| P2 | Route/body text is reassigned and remeasured every periodic refresh (`Runtime.lua`, one-second `OnUpdate`; `UI.lua`, `Render`). Scroll frame has no intentional reset/preservation rule when route identity changes. | Stable plans generate needless text layout; a scrolled route can hide a newly changed next stop or preserve an irrelevant offset. | Cache display strings or skip unchanged assignment; define route-change scroll behavior and clamp overflow after content shrinks. Add meaningful scroll/route-change regression checks. |
| P2 | Feedback clear mutates persistence immediately and export edit box is editable without a read-only reconstruction affordance (`UI.lua`, `ShowFeedback`). Save clears entry unconditionally and success is only a chat print (`Runtime.FeedbackAction`). | Accidental clear loses captured data; an edited visible report can look authoritative until regenerated; save acknowledgment is remote from input. | Confirm UI clear, retain slash semantics, show local save feedback, reset generated report on reopen, and prevent display edits from changing saved report. Preserve feedback ring/counters/schema. |
| P2 | Build identity parses the exact route-feedback suffix (`UI.lua`, `Render`) and manifest is release 0.2.0. | A UI-only development build can look like approved build 8 even though its implementation differs; changing capture tag syntax can show `?`. | Add explicit UI development identity independent of release capture-version parsing; do not relabel the approved installed baseline. Ensure development package filename cannot overwrite approved ZIP. |
| P3 | Package privacy scanner covers a fixed public source list excluding `HANDOFF.md` and newly added `docs` (`scripts/package.py`, `SOURCES`). | Review documents/evidence can be committed without the same privacy gate as shipped source. | Extend privacy coverage to newly public text or run a complete staged-file scan before commit; exclude private screenshots and game data. |

Preserve during the pass: planner modules and catalogue data; schema-3 settings; existing feedback records/counters; one-owned-waypoint cleanup and manual-arrow noninterference in `Navigation`; guarded event registration and one-second update cadence. UI simulation stubs deliberately omit rendering, event security, font metrics and native scroll behavior, so passing them does not establish Forever compatibility. No conclusion about real combat taint or frame performance can be drawn from this source-only review.
