# Independent initial review: visual design

Reviewed approved build 8 source and existing UI simulations before seeing other reviews or a proposed redesign. This is a source-based visual critique, not an observation of live game rendering. Severity: P1 blocks reliable reading/action; P2 materially reduces clarity; P3 polish.

| Severity | Concrete weakness and evidence | Player impact | Highest-value improvement |
| --- | --- | --- | --- |
| P1 | Compact current content can overlap its footer: a 360-wide frame places Waypoint at x14..106, Auto at x114..226, and Feedback at x238..346; the controls fit horizontally, but text and status/content are not region-bounded. Current text starts below y94 and has a fixed 190 height while footer/status anchor to a variable 190..352 frame (`UI.lua:100–108, 213–215`). | Long objectives/notices can occupy the same area as status/buttons; the player cannot trust the window's reading order. | Give current content a bounded scroll viewport between a measured header and permanent footer. Keep footer outside the content region. |
| P1 | Expanded current text is fixed to 100 high, but summary is anchored at y208 independently (`UI.lua:101,109,214`). Instruction itself is capped at 36 high (`73–74`). | Multi-line names or several objectives truncate or collide with summary; next action becomes less visible in the layout intended to expose detail. | Measure the heading, reserve its natural height, and flow remaining regions with explicit bounds. |
| P2 | Single-member instruction repeats the quest name immediately in member text (`Instruction`, `Render:186–192`); grouped instructions are generic while every member uses the same small font. | Valuable vertical space is spent repeating information; the main verb competes with detail. | Separate a short action eyebrow from the quest/objective headline and subordinate progress/location. |
| P2 | Almost all information uses GameFontHighlightSmall and all route body content is one FontString (`UI.lua:4,125,219–236`). | Quest names, progress, notes and diagnostics have weak visual distinction; large routes read like a log dump. | Use three clear type roles: heading, readable objective body, muted metadata. Use consistent spacing and explicit stop numbering. |
| P2 | Technical IDs (`[quest %d]`) and coordinates repeat on every route member; permanent footer explains implementation estimates and commands (`UI.lua:127,229–234`). | Details useful to debugging dominate routine play and reduce scan speed. | Remove IDs from ordinary tracker; show destination once per stop and retain technical information in exported feedback/help. |
| P2 | Zone name and build share a 332-wide, 12-high unwrapped strip in both sizes (`UI.lua:94,180`); whole frame uses a strong mint tooltip border but default bronze buttons (`85–86`, button helper). | Long zone labels compete with build identity; accent and native controls have no coherent visual hierarchy. | Keep identity short, put zone in context/status, and reserve a restrained accent for current action, with neutral panel borders. |
| P2 | Feedback presents a report editor directly alongside Save and destructive Clear, without a distinct confirmation/status area (`UI.lua:141–172`). | Saving a note has little local visual confirmation; clear looks as routine as selecting export text. | Separate note capture from export, label note input, add concise saved confirmation, and make clear a deliberate second action. |
| P3 | Expand/minimize and close use raw `+`, `-`, `x` labels (`UI.lua:97–99`) without explanatory hover text. | Discoverability relies on prior UI knowledge and default button appearance. | Add tooltips naming the action and retain consistent button sizing/spacing. |

Priority order: fix bounded reading regions and long text first; establish current-action hierarchy second; remove repeated diagnostics and tame metadata third; unify feedback interaction and controls fourth. A calm dark native panel with readable warm-white body text, gold action headings, one restrained green navigation accent, and consistent inset rhythm would fit WoW without requiring custom artwork.
